# perfsim-block-extractor

### [BlockExtractor.h](BlockExtractor.h)

Adapted performance simulator backend. Gathers the basic blocks and how often each basic block is executed. Once the simulation finishes, it generates a .json file containing the basic blocks, including their instructions and relative count of each observed dynamic delay.

Must be installed to [`SoftwareEval-Backends/include/internal`](https://github.com/tum-ei-eda/SoftwareEval-Backends/tree/main/include/internal).

> **Note:** Currently only supports CV32 variants

> **Note:** Must be incorporated into the factory ([`SoftwareEval-Backends/src/api/Factory.cpp`](https://github.com/tum-ei-eda/SoftwareEval-Backends/tree/main/src/api/Factory.cpp)), similar to how performance models for different code-variants are setup.

### [BlockExtractor.cpp](BlockExtractor.cpp)

Must be installed to [`SoftwareEval-Backends/src/internal`](https://github.com/tum-ei-eda/SoftwareEval-Backends/tree/main/src/internal).

### [BlockInstructionGenerator.h](BlockInstructionGenerator.h)

Adapted Block Instruction Generator. M2-ISA-R-Perf generates instances of `BlockInstruction` for each instruction in an ISA. Each instruction indicates whether it uses the i-cache, d-cache, or divider resource model.

Must be installed to [`SoftwareEval-Backends/include/internal`](https://github.com/tum-ei-eda/SoftwareEval-Backends/tree/main/include/internal).

### [extract_basic_blocks.py](extract_basic_blocks.py)

Extracts the most relevant basic blocks from the .json file generated by the BlockExtractor and transforms it in the expected layout for the code analyzer.

**Signature:**

```bash
python3 extract_basic_blocks.py <path-to-experiment> [-h] [-t PERCENTAGE] [-p] [-s [KEY]] [-e OUTPUT_DIR] [-d [METRIC]] FILE
```

- `-h`: Help
- `-p`: Prints detailed information about each basic block (instructions)
- `-t`: Defines the threshold percentage to filter out only the relevant basic blocks.
- `-e`: Exports the filtered basic blocks to the given directory.
- `-s`: Sorts the basic blocks accordingly. Keys: 
  - `pc`: sort by pc/instr. address
  - `id`: sort by basic block id
  - `weight`: sort basic blocks by their weight/relevance
- `d`: Extracts the dynamic delays (if any are present) gathered during performance simulation. Keys:
  - `app_average`: Average of all delays over all executed instructions, per delay category (e.g. i$, d$, div, divu)
  - `bb_average`: Average of all delays over per basic block and per delay category
  - `bb_comb`: Builds combinations of delays per basic block and per delay category
  - `instr_average`: Average delay per unique instruction (by pc), per delay category (e.g. i$, d$, div, divu)
  - `instr_round`: Rounds the average delays of each unique instruction

> **Note:** Hardcoded to check for dynamic delays of "iCache", "dCache", "div", "divU"

**Example Usage:**

Include all basic blocks that have a relative weight of >= 1%:

```bash
python3 extract_basic_blocks.py CV32E40PXISAAC_edn_BlockList -t 1 -e exported_edn/
```

The CPI-analysis can then be executed using:

```bash
BENCH=exported_edn/
python3 ./main.py <path/to/dump_dir> --files $BENCH/experiment.json --cores="*" --cpi --rank
```

Symbolic analysis of all custom instructions:

```bash
BENCH=exported_edn/
python3 ./main.py <path/to/dump_dir> --files $BENCH/experiment.json --cores="*V0" --cpi --rank --sym CUSTOM
```
