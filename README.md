# Code Performance Analyzer (WIP)

This Python tool attempts to predict the CPI (cycles per instruction) of a processor for one or multiple code blocks by statically analyzing each code block.

The code blocks are usually expected to be (pseudo) basic blocks but it is also possible to analyze code blocks that contain multiple branch instructions.
However, delays due to branch prediction cannot be accounted for as of now (2026-05).

The tool requires [*M2-ISA-R-Perf*](https://github.com/mariusalexander/M2-ISA-R-Perf/tree/implement-block-scheduling-model).
It uses the scheduling functions of each instruction in code sections and updates an timing model.
Similarly to the Performance Estimator, data hazards and structural hazards may be detected that influence the CPI.
By comparing predictions for varying microarchitectures, design space exploration may be facilitated without the need to simulate all variants.

## Requirements

> Note: Python version > 3.10 is required

1. Create a virtual Python environment and activate it:

    ```
    $ python3 -m venv venv
    $ source venv/bin/activate
    ```

2. Install the Python dependencies:

    ```
    $ pip install -r requirements.txt
    ```

3. This tool depends on *M2-ISA-R-Perf*, which does not yet provide a Python package. To use this application, extend `PYTHONPATH` accordingly:

    ```
    $ PYTHONPATH=<path/to/M2-ISA-R-Perf/m2isar_perf> python3 main.py ...
    ```

## Usage

Make sure to activate the virtual Python environment before running this tool:

```
$ source venv/bin/activate
```

### Signature: (WIP)

```
$ PYTHONPATH=... python3 main.py [-h] [-v] [-p] [-b] 
            schedule_model [struct_model]
            [--tests] [--examples [EXAMPLES]] [--files FILES [FILES ...]]
            [--cores CORES]
            [-d DEFAULT_DYNAMIC_DELAY]
            [--symbolic-analysis SYMBOLIC_ANALYSIS] [--sequence-analysis]
            [--cpi] [--xisaac]
            [--export EXPORT] [--export-suffix EXPORT_SUFFIX]
            [--block-schedule] [--schedule-graph] [-o OUT_DIR]
```

Use the `--help` or `-h` option to get an overview of supported input arguments:

```
$ PYTHONPATH=... python3 main.py --help
```

`PATTERN` = Wildcard-pattern. Use `*` matches everything, `?` matches single character. Preprend pattern `-` to invert selection (not a standard Wildcard character).
`FILES`   = List (separated by spaces) of file(path)s.
`DIR`     = Existing directory.
`LIST`    = Comma-separated list of strings.

**Positional arguments:**

- `<path/to/dump_dir>` Path to the  directory that contains both the `schedule.model` and `frontend.model` generated by *M2-ISA-R-Perf* using the `-d` option.

Alternatively specify both models separately:

- `<path/to/schedule.model>` Path to schedule model generated by *M2-ISA-R-Perf* using the `-d` option.
- `<path/to/frontend.model>` Path to structural model generated by *M2-ISA-R-Perf* using the `-d` option.

**Options:**

- `-v` Enable verbose output (especially for schedule analysis).
- `-p` Prints the schedules of each basic block and each variant in a table.
- `-b` Prints the code-blocks.
- `--cores=PATTERN` Wildcard pattern matching the variants to use for further processing.
- `--files=FILES` Parses code blocks from disk. Multiple input files can be specified. Alternatively pass metadata file (`experiment.json`), containing weights for BBs.

Other:

- `--examples=PATTERN` Loads example code blocks. An optional Wildcard pattern can be used to load only certain code blocks.
- `--tests=PATTERN` Executes all unittests (WIP - no meaningful tests yet, mostly used as a playground).
- `--export=DIR` export results to given path

**Targets:**

- `--seq` Performs sequential schedule analysis (default).
- `--sym=LIST` Performs symbolic list by interpreting the latency of the given micro-actions as symbolic.
- `--cpi` Predicts the total CPI for all basic-blocks and microarchitectures, requires relative weights of BBs.
- `--rank` (WIP) Attempts to rank all analyzed microarchitectures.
- `--xisaac` (WIP) Assumes all microarchitectures to have the same pipeline structure, mostly of interest for symbolic analysis.

Other:

- `--schedule-graph` Generates schedule graphs similar to *M2-ISA-R-Perf* depicting the entire code block. Uses `-o` flag to change output directory (defaults to `out`).


### Examples:

1. Estimate the CPI for all example code blocks:

    ```
    $ PYTHONPATH=... python3 main.py <path/to/dump_dir> --examples="ex*" --cpi --rank
    ```

2. Interpret micro-actions as symbolic (here `ALU` and `MUL`):

    ```
    $ PYTHONPATH=... python3 main.py <path/to/dump_dir> --examples="ex*" --cpi --rank --sym=ALU,MUL
    ```
