# Performance Prediction Tool

This Python tool attempts to predict the CPI (cycles per instruction) of a processor variant for one or multiple code blocks by statically analyzing each code block, or more precisely each basic block.

For each instruction in a basic block, the corresponding scheduling functions is evaluated and merged into a timing model.
Once all instructions are evaluated, the CPI is calculated by taking the executed cycles and executed instructions into account.
The overall CPI of a processor variant executing an application is extrapolated by weighing the CPI of each basic block according their weights.
Data hazards and structural hazards that influence the CPI may be detected.
By comparing predictions for varying microarchitectures, design space exploration may be facilitated without the need to simulate all variants.

The approach is based on the [*Performance Estimator* (for ETISS)](https://github.com/tum-ei-eda/etiss-perf-sim).

## Requirements

> Note: Python version > 3.10 is required

The tool requires a patched [*M2-ISA-R-Perf*](https://github.com/mariusalexander/M2-ISA-R-Perf/tree/implement-block-scheduling-model), that allow exporting the structural and schedule model as pickle files.

1. Initialize the submodules:

    ```
    $ git submodule update --init --recursive
    ```

2. Create a virtual Python environment and activate it:

    ```
    $ python3 -m venv venv
    $ source venv/bin/activate
    ```

3. Install the Python dependencies:

    ```
    $ pip install -r requirements.txt
    ```

4. This tool depends on *M2-ISA-R-Perf*, which does not yet provide a Python package. To use this application, use:

    ```
    $ source .env
    ```

    or alternatively extend the `PYTHONPATH` accordingly:

    ```
    $ PYTHONPATH=<path/to/M2-ISA-R-Perf/m2isar_perf> python3 main.py ...
    ```


## Usage

Make sure to activate the virtual Python environment before running this tool:

```
$ source venv/bin/activate
```

Make sure to update the environment / update `PYTHONPATH`:

```
$ source .env
```

### Signature:

```
$ python3 main.py <path/to/dumped_models>
        [-h] [-v] [-p] [-P] [-n NUM] [-d DELAY] 
        [--rank] [--cores WILDCARD] [--xisaac]
        [--export EXPORT_DIR] [--export-suffix EXPORT_SUFFIX] 
        [--examples [WILDCARD]] [--files FILES [FILES ...]] 
        [--sequence-analysis] [--symbolic-analysis OP1,OP2,OP3]
        [--cpi] [--schedule-graph]
```

Use the `--help` or `-h` option to get an overview of supported input arguments:

```
$ python3 main.py --help
```

`WILDCARD` = Wildcard-pattern. Use `*` matches everything, `?` matches single character. Preprend pattern `-` to invert selection (not a standard Wildcard character).

**Positional arguments:**

- `<path/to/dumped_models>` Path to the directory that contains both the `schedule.model` and `frontend.model` generated by *M2-ISA-R-Perf* using the `-d` option.

Alternatively specify both models separately:

- `<path/to/schedule.model>` Path to schedule model generated by *M2-ISA-R-Perf* using the `-d` option.
- `<path/to/frontend.model>` Path to structural model generated by *M2-ISA-R-Perf* using the `-d` option.

**Options:**

- `-v` Enable verbose output (especially for schedule analysis).
- `-p` Prints the schedules of each basic block and each variant in a table.
- `-P` Prints the code-blocks.
- `--cores=WILDCARD` Wildcard pattern matching the variants to use for further processing.
- `--export=DIR` export results to given path. Directory is created if it does not exist
- `--rank` groups/ranks the variants according to their predicted CPI value

Other:

- `-n` analyses only the first `n`-variants
- `-d` defines a default delay with which all dynamic delays (if any) are replaced with
- `--export-suffix` optional suffix which is appended to the exported results

**Inputs:**
- `--files=FILES` Parses code blocks from disk. Multiple input files can be specified. Alternatively, pass a metadata file (e.g. `experiment.json`), containing a list of basic blocks and their weights.
- `--examples=PATTERN` Loads example code blocks. An optional Wildcard pattern can be used to load only certain code blocks.

**Targets:**

- `--cpi` Predicts the total CPI for all basic-blocks and microarchitectures, requires that each basic block is weighted.
- `--seq` Performs sequential schedule analysis (default).
- `--sym=OP1,OP2,OP3` Performs symbolic schedule analysis by interpreting the latency of the given micro-actions as symbolic.
- `--xisaac` Indicates that the latencies for the symbolic micro-actions should be inferred from the variants. This option requires an XISAAC-variant generted by GenIE. 

Other:

- `--schedule-graph` Generates schedule graphs similar to *M2-ISA-R-Perf* depicting the entire code block. Use `--export` path to change the output directory (defaults to `./out/`).


### Examples:

The directory `examples/` contains sample basic blocks extracted from embench applications. All models use only static delays.

1. Estimate the CPI using sequential analysis for `aha-mont64`, for the first variant only (V0):

    ```
    $ python3 main.py examples/aha-mont64 --files examples/aha-mont64/exported/experiment.json --cpi --rank --seq --cores="*V0" -p
    ```

2. Estimate the CPI using symbolic analysis for `aha-mont64`, for all custom instructions. Infer delays for symbolic variables from variants:

    ```
    $ python3 main.py examples/aha-mont64 --files examples/aha-mont64/exported/experiment.json --cpi --rank --sym CUSTOM --xisaac --rank 
    ```

3. Estimate the CPI using symbolic analysis for `aha-mont64`, for all custom instructions. Use sample latencies for each symbolic variable (1, 2, 3):

    ```
    $ python3 main.py examples/aha-mont64 --files examples/aha-mont64/exported/experiment.json --cpi --sym CUSTOM
    ```

### Other Example Basic Blocks:

1. Estimate the CPI for all example code blocks:

    ```
    $ python3 main.py examples/simple_riscv --examples="ex*" --cpi --rank
    ```

2. Interpret micro-actions as symbolic (here `ALU` and `MUL`):

    ```
    $ python3 main.py examples/simple_riscv --examples="ex*" --cpi --rank --sym=ALU,MUL
    ```

3. Visualize the basic block scheduling function of a basic block:

    ```
    $ python3 main.py examples/simple_riscv --examples="ex_adds" --schedule-graph
    ```
